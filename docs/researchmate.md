# Alur ResearchMate

ResearchMate berfokus pada proyek riset akademik. Peneliti merumuskan pertanyaan, mengumpulkan artikel dan PDF, membandingkan temuan, menilai kandidat celah riset, lalu menyusun laporan yang rujukannya dapat dibuka ulang. Konsep agen meliputi Planner, Discovery, Analysis, Synthesis, Research Gap, dan Verification.

ITS Academic menyediakan autentikasi, daftar proyek pribadi, formulir masukan, dan tinjauan rencana awal berbasis aturan. Tinjauan menerima pertanyaan riset, jumlah artikel/PDF, dan mode sumber. Pengguna dapat menyimpan rencana tersebut sebagai proyek dalam akunnya setelah memberi judul dan ringkasan, lalu membuka detailnya dari dashboard. Tombol rencana baru mengosongkan draf sesi. Formulir ini hanya menyarankan langkah persiapan; ia tidak membaca isi PDF, menelusuri indeks ilmiah, atau menghasilkan matriks literatur otomatis.

Backend chat terpisah tersedia melalui API Sanctum. Pengguna masuk untuk memperoleh token Bearer satu jam, mengirim prompt, lalu menerima jawaban Ollama dalam JSON atau SSE. System prompt ResearchMate mengarahkan respons pada perencanaan dan penilaian riset serta meminta verifikasi sumber. Jika Ollama gagal sebelum mengirim teks, aplikasi mencoba Senopati apabila URL, model, dan kunci aksesnya sudah dikonfigurasi. Setelah teks mulai dikirim, kegagalan menghasilkan event error tanpa mengulang jawaban ke provider lain. Jawaban yang selesai tersimpan bersama pengguna, prompt, model, provider, dan penggunaan token; statistik token yang tidak disediakan provider tetap `null`. Antarmuka chat Livewire belum termasuk tahap ini. Lihat [kontrak API](api.md).

Database PostgreSQL menyimpan pengguna, proyek, rencana riset, masukan, token Sanctum yang di-hash, dan riwayat chat. Data proyek contoh tersedia dari seeder. Pembuatan proyek melalui alur rencana riset sudah tersedia; penyuntingan proyek belum tersedia. Pernyataan kandidat celah riset dan kutipan dari model tetap perlu diperiksa terhadap sumber asli.

Panel AdminLTE menampilkan jumlah pengguna, proyek, dan masukan dari database. Admin dan Staf dapat mencari proyek; hanya Admin dengan permission `projects.delete` yang dapat menghapusnya. Akun dan data contoh serta tombol masuk instan dibatasi pada lingkungan pengembangan lokal.
